# Park

The REACT COMPOSITION API — the top architectural layer, AND the home of the fleet-wide composable-component convention. Compose an entire park as JSX on ONE shared canvas instead of hand-writing an imperative `build`: `<Park>` renders a single Stage (full-screen by default, autoRotate OFF, fog, terrain-clamped camera), the `<GameManager/>` child declares the ONE `createGameManager`, clickability comes wired (ride click → RideViewer with onboard cam, guest click → GuestInfo — one floating window at a time), ParkInfo mounts bottom-right and `validatePark` runs one frame after the children settle. Every child is a thin declarative wrapper over the existing imperative builders — the recipes in `rules/park-generation.md` still apply unchanged; the wrappers just execute them. This is a HAND-ROLLED context, NOT react-three-fiber.

**The composing agent's flow:** seed a `<Terrain>` → lay `<Paths>` → declare `<GameManager/>` → mount the `<Gate>` (park entrance) → creatively place attractions straight from the catalog (`<FerrisWheel position rotation register/>`, `<BurgerShop register/>`, `<Torch/>`, …) → scenery. Once the `<GameManager/>` exists, ALL game logic is free: guest spawning/needs/goals, ride FSMs + breakdowns, queues, purchases, litter, and the UI windows.

**Composition order is mount order.** Sibling effects run in JSX order, so declare `<Terrain>` → `<Paths>` → `<GameManager>` → `<Gate>` → rides/stalls/amenities → scenery, exactly like the imperative build order. Wrappers throw a descriptive error when a prerequisite is missing.

```tsx
<Park seed={7} climate="temperate" size={16} guests={10} onReady={(report) => {/* ok? */}}>  {/* compact demo — omit `size` for the EXPANSIVE 48 default and SPREAD OUT (districts, 4+ rides) */}
  <Terrain keepDry={KEEP_DRY} coasterPts={COASTER_PTS} />
  <Paths nodes={NODES} edges={EDGES} plazas={[PLAZA]} walkers={4} bins={[[1.5, 2.4]]} />
  <GameManager />
  <Gate />
  <Coaster name="Timberline Run" points={COASTER_PTS} type="wooden" capacity={3}
    queueTailNode={12} queueDir={[0, -1]} exit={[-3.6, 1.2]} exitDir={[1, 0]} deck={[-4.31, 0]} />
  <FerrisWheel position={[6.69, -2.4]} rotation={-Math.PI / 2} register={{ name: 'Grand Wheel', capacity: 4 }} />
  <BurgerShop position={[3.0, -0.5]} rotation={-Math.PI / 2} register price={3} value={5} />
  <Fountain /> <Restroom position={[-1.2, 4.8]} rotation={Math.PI / 2} />
  <Torch position={[1.65, 4.05]} /> <Neon text="ARCADE" position={[3.6, 1.7, -6]} rotation={Math.PI} />
  <Scenery name="planterBox" position={[1.65, 0.75]} /> <Lights from={[-0.95, -1.2]} to={[0.95, -1.2]} />
  <Placed build={(t) => tree(t, { shape: 'pine' })} position={[-2.8, 4.6]} />
</Park>
```

## The composable convention (fleet-wide)

Every catalog component exports ONE React component that COMPOSES: it mounts its built group into the surrounding scene context and renders null. **No component renders a `<Stage>`** — the only Stage owners are `<Park>` and `<ScenePreview>` (the host `*.previews.tsx` files use). All of it is exported from here:

- **`useComposable(build, { position, rotation, scale, deps }) → boolean`** — the primitive: `build(t, park) → Group | { group, update?, dispose? }` runs in an effect, mounts via `addObject` with the prop transform (y settles via `floorAt` unless `[x, y, z]`), cleans up on unmount, REMOUNTS on prop change (`deps` = extra remount key; builder identity is NOT a key). Returns false outside any scene context.
- **`composable(displayName, build, cfg?)`** — the factory: `build(t, props, park)`; `cfg.props` defaults; `cfg.compose(park, { built, props, position, rotation, scale }) → cleanup?` is the registration hook, run ONLY in real parks (never under a preview host).
- **`<ScenePreview distance targetY autoRotate ground background night height fog groundAt seed dress>`** — the preview Stage host: provides the same context (usePark works; `groundAt`/`floorAt` → 0), `dress(t, g, api)` builds staging around the children and may return an updater. Keep previews pixel-identical: same Stage props as the old per-component Stage.
- **`<ConfigurableRide build layout register name capacity rideDuration loadTime intensity price queue position rotation scale>`** — the universal ride chassis (every catalog ride renders one via `composableRide(displayName, build, layout)`). With `register` (or any top-level sim prop) inside a real `<Park>` it does EVERYTHING: `registerRide` (FSM: waiting → departing → travelling → brokenDown/beingRepaired; the builder's `onStateChange` spins the visual down/up), queue lane + entrance/exit huts derived from position+rotation via `layout` (`front` — queue HEAD out the local +z face, default 1.8; `exit` local `[-1.5, 1.35]`; `board` local `[0, 0.25, 0]`; `defaults` — per-ride name/capacity/duration/intensity/price), `groundRideAccess` grounding, `seatWorld` pass-through (real guests ride the vehicle), `crashed` crash wiring, `userData.rideRef` (click → RideViewer) + `userData.rideVehicle` (onboard cam). `queue={{ anchor, dir }}` overrides the derived lane in world space. LANE LENGTH (round-2 safeguard): the derived lane always rotates with the ride (its axis is the yaw-rotated local +z); by default it is `laneLenOf(capacity)` long, but when a STREET NODE sits on the lane axis short of the default tail reach (`front + laneLenOf(capacity) + 0.35`) the lane is TRIMMED so its tail lands exactly on that node — layouts planned against the documented `1.8 + 0.35·capacity + 0.35` footprint used to have their lanes overshoot the street and spear into a facing ride's lane. Never extended; ≥ 1.2 u of lane is kept; explicit `queue` overrides opt out. Place rides so a street node sits on the +z lane axis within that reach. `registerComposedRide(park, built, reg, at, layout, queue?)` is the underlying helper.
- **`<ConfigurableStall build stall register name price value>`** / **`composableStall(displayName, build, saleDefaults)`** — the shop chassis: `registerStall` with the anchor at the settled position and the serving front facing local +z (attach point 0.72 out — aim `rotation` at the customers' path). Guests then hunger/thirst-seek it, buy, and litter.
- **`<GameManager guests?>`** — declares the sim explicitly (mount right after `<Paths>`). Legacy parks that never mount it still get a lazily-created manager (with a console note), but the JSX child is THE way.

**Exemplars:** `FerrisWheel` (ride: seatWorld gondola riders, FSM spin-down, vehicle cam, layout geometry in its doc comment), `BurgerShop` (stall + `withGuest`), `Torch` (simple + rich preview dress), `GrassTile` (minimal). The demo park composes all of them, `validatePark ok: true`.

**Migration checklist** (any new/remaining component): 1) extract the builder `build<Name>[Scene](t, opts?) → { group, update? }` (+ `seatWorld`/`vehicle`/`onStateChange`/`crashed` on rides); 2) componentize with `composable`/`composableRide`/`composableStall` — keep every existing export; 3) previews render the component inside `<ScenePreview>` with the SAME Stage props (staging → `dress`); 4) cleanup audit (dead code, unused imports) + esbuild + day/night screenshots standalone AND composed (rules/asset-testing.md still gates).

**Track piece composition (future work):** tracked rides will take pieces as props/children compiled to spline control points (TrackKit-style). Not built yet — do not hand-roll per-ride piece APIs.

Exports:

- **`<Park seed climate size fullscreen height validate guests background fog distance cameraPose quality budgets onReady>`** — the one canvas + sim + UI shell. `fullscreen` defaults **true** (rules/ui.md); `validate` defaults **true**: one frame after the children mount it spawns `guests` (default 12) at the gate, runs `validatePark` (net/manager/terrain/registered coasters/extra footprints/scene group, plus `gridNodeCount` so diagonal street edges FAIL), logs the report, shifts the render clock past the sim smoke run (by the report's `simSeconds` — the window scales with the longest registered rideDuration) and calls `onReady(report, { manager, api })`. `size` defaults to the EXPANSIVE **48** (sizes to 96+ compose + validate; everything downstream — terrain seg density, composition zone counts, validators, orbit distance — scales with it). `fog` defaults to the classic haze, or `{ near, far }` culling fog when `size > 20` (so the default 48 gets culling fog — pair with the ride runtime's LOD tiers). `quality` (default `'medium'`) picks the Stage rendering tier; `budgets.lights` (default 16) caps simultaneously ACTIVE PointLights park-wide. Prop changes on `<Park>` itself need a remount (`key`).
- **The ride runtime (automatic):** every mounted object is LOD-scheduled — NEAR full detail every frame; MID every 2nd frame, `userData.lodDetail` children (passengers, cockpit dressing) hidden; FAR every 4th frame, particles + its PointLights shed (static silhouette); OFFSCREEN paused to a 32nd-frame keep-warm tick. Distances are measured against ALL cameras (orbit + insets), boundaries have hysteresis, and updaters take absolute time so throttling never slows or drifts motion. A `[Park] perf:` line logs ~3 s after settle. See SETUP.md §13.
- **`usePark(consumerName?)`** → `ParkContextValue` for custom children: `{ three, root, api, seed, size, climate, addObject(obj, updater?, { lod }?) => cleanup, manager(), ground, paths, composition, groundAt(x,z), floorAt(x,z) (plaza-aware), registerFootprint(rect), registerCoaster(c), reportLint(kind, detail, fatal?), registerPlanted(p), registerBlocker(spec) }`. `registerBlocker({ rect | circle, label, kind?, owner?, pad?, height? })` declares a SOLID obstacle guests must walk around (round-6 — see below); it forwards to the GameManager's blocker registry and returns the unregister (a no-op before `<Terrain>`/`<Paths>` exist and under `<ScenePreview>`). `addObject` registers a ride-runtime entry — pass `{ lod: 'full' }` for park-spanning backdrops that must never throttle. `manager()` creates the ONE GameManager lazily (requires `<Terrain>` + `<Paths>` mounted; its group joins the scene automatically).
- **`<Terrain seed? climate? size? keepDry coasterPts seg?>`** — `parkComposition` (probed landform under YOUR guards) + `buildTerrain` + `tintTerrainForClimate` + ONE `buildWater` sheet; registers `heightAt` as the Stage ground sampler. Always the first child. **Guards are POST-ENFORCED (round-3 safeguard):** the composition's `clampPeaks`/`clampBasins` are built into the real terrain, so every `keepDry` cell and coaster footing comes out dry and bulge-free even when no probe seed satisfied the rules — `comp.report.violations` (what validatePark receives) reflects the post-clamp ground.
- **`<Paths nodes edges plazas grid nodeY width walkers bins>`** — the lattice street skeleton: `snapNetToGrid` safety pass, ONE path level (max ground under nodes + 0.03), `buildPathNetwork` (grid lint default ON), `bermNetToGround`, ambient `attachWalkers`, bin meshes + manager bin registration. CAUSEWAY LINT (re-armed round-6, now §0-FATAL): two tests — the path level sitting > 0.8 u above the MEDIAN ground under the nodes (one node on a rise lifts the whole network onto tall berms) AND **every rendered SPAN sampled against the ground beneath it** — a street whose nodes all sit high but whose span crosses a river bank is quietly put on a wooden viaduct, and a round-6 park hoisted an edge 2.21 u with the old node-only lint silent. A span lifted > 1.0 u is recorded as a FATAL park lint (`validatePark` fails it, check `autofix`) — reroute the edge, add an intermediate node on buildable ground, or `nodeY`-ramp down to it. Diagonal street edges are promoted from a lint warn to a validatePark FAIL.
- **`<Gate position? rotation?>`** — `buildParkEntrance`, plinthed, `registerParkEntrance` = the SOLE guest spawn. DEFAULT position snaps to the lattice cell hugging the FRONT (+z) terrain edge (z = `1.2·round((size/2 − 0.8)/1.2)`: **22.8 on the default 48**, 7.2 on a compact 16 — within ~1 u of the edge, facing OUT; round-3 safeguard: the old default sat 2 u inside and failed validatePark's gate-at-edge check). Keep a street node under the gate cell.
- **`<Coaster points type bank name capacity rideDuration loadTime intensity price cars colours queueTailNode queueDir exit exitDir deck>`** — `points` are `[x, yAboveRef, z]` (the 80th-percentile ground-reference trick is applied for you; points 0-2 = the station straight, levelled flat). Builds `buildRideSpline` + a ColorKit-preset train + station deck, plans the queue/hut assembly with `planRideAccess`/`groundRideAccess` (queue TAIL on street node `queueTailNode`), registers with the manager (`vehicleHandle` crash wiring included), tags `userData.rideRef`/`rideVehicle`, and registers the circuit for validatePark's legality + crash checks. Pieces mode forwards the park size as `compileTrackPieces` `bounds`; a FATAL compiled circuit (checks failed / closure > 40% of the authored length / out of bounds) is rendered as a TRANSLUCENT RED invalid track with NO train, is NOT registered with the manager (guests never queue for it), console.errors the fix (end the layout FACING the station; keep every piece inside ±size/2) and fails validatePark hard. **POINTS mode runs the SAME fatal gate (round-2 safeguard)** — `checkCoasterDesign` (hard violations) + `validateSpline` (≥ 0.9 clearance) + park bounds (±size/2 + 0.4) over the as-built world points; `points` used to bypass every guard and run a 1.9 g out-of-bounds circuit as a live ride. `<TrackRide>` applies the same guard (bounds checked through its mount transform; previews are exempt). Required props (`queueTailNode`/`queueDir`/`exit`/`exitDir`, `deck` shape) are validated up front with named errors. **Queue-orientation safeguard (round-4):** the lane hangs off the FIXED tail node, so a `queueDir` aimed along the station row spears the ride's own pad/deck — the wrapper now auto-FLIPS to the first orientation of dir/-dir/perpendiculars whose lane + entrance hut clear the ride's own boardPoint pad/station straight/deck and stay in bounds (preferring one that also clears the planned exit), relocates the exit hut when the re-oriented lane runs over its cell, and `console.warn`s every choice (warnings are FATAL per the recipe book — fix the plan). `registerComposedRide`/`<ConfigurableRide>` apply the same safeguard to derived/provided lanes (explicit `queue.anchor` opts out). The circuit registers for validatePark WITH the ride name so the round-4 track-corridor sweep can exempt the ride's own access rects. Pieces-mode `start` accepts `[x, z]` OR the same `[x, y, z]` tuple given to `compileTrackPieces` (round-3 safeguard: a V3 start used to be read as `[x, z=y]`, shifting the whole circuit out of bounds), and `bank` SATURATES at the type's bankLimit (`coasterBankCap` — wooden 25°, steel 55°; the registered bank matches what is built, so validatePark's re-check agrees).
- **`<FlatRide build position name capacity rideDuration price intensity colours queueTailNode queueDir exit? exitDir?>`** — generic flat ride: your deterministic `build(t, { position, padTop, groundAt, scheme })` → `{ group, update?, seatWorld?, boardPoint? }` makes the visual (place it at `info.position`/`padTop` yourself); the wrapper wires the queue/hut assembly + registration. `exit`/`exitDir` are OPTIONAL (round-2 safeguard): omitted, the exit hut is auto-derived the way the register wrappers derive theirs — the local `[-1.5, 1.35]` cell in the queue frame (+z = normalized `queueDir`), doorway facing the frame's −x (beside the queue face, opposite side of the lane). All required props are validated up front with named errors (`"<FlatRide> 'X': exit must be [x, z] …"`) — a missing prop used to crash the whole page with a raw `undefined[0]` TypeError before anything mounted. STRANDED-AT-ORIGIN GUARD: a builder that ignores `info.position` (group AND geometry both > 0.5 u off the cell) has its group moved onto the cell with a warn, and a post-mount audit warns loudly whenever the mounted visual still sits > 0.5 u from `position` — sim pads must never register at an empty cell.
- **`<Placed build position rotation scale>`** — the escape hatch: mounts ANY `(t, park) => Group | { group, update? }` at a settled position. It goes through the same ride runtime as every wrapper (LOD throttling, light budget), but prefer the composable catalog components / `composableRide` for rides — they add queue/hut/sim wiring on top of the same policy. Use `<Placed>` for Kit/Rock pieces and one-off dressing. Round-6: like `<Scenery>` it registers its GROUND-CONTACT footprint (the XZ extent within 0.45 u of its base — a tree canopy may overhang a path, its trunk may not), so `validatePark` fails a willow planted inside the waterline or a prop blocking the walked surface. AUDITS: a built group that already carries its own position (> 0.5 u off the local origin) warns — `<Placed position>` is added ON TOP; and a `build` function whose NAME matches `/Scene$/` (a `build<Name>Scene` preview stage builder) warns inside a real park — preview scenes are staging, use the component or its `build<Name>()` builder (best-effort name check, also applied by `useComposable`; wrapped/anonymous builders pass through undetected).
- Amenities: **`<Stall kind="balloon" position rotation sell?>`** (plinthed; routed through `<ConfigurableStall>` — round-3 safeguard: it now REGISTERS with the manager and carries catalog-stall userData tagging instead of being invisible to both; `sell` is `true` for the kind's sale defaults — balloon: item 'balloon', price 2, value 3 — or an override object), **`<Restroom position rotation>`** (registered — guests use it; the hut is a BLOCKER with its doorway left clear), **`<Fountain position? scale?>`** (defaults to the first plaza's centre; the basin is a circular BLOCKER — guests walk round it), **`<Torch position height?>`**, **`<Neon text|path color secondary scale backboard? position rotation posts?>`** (night-gated marquee on iron posts; default scale is AUTO — capped so the sign never exceeds ~2.5 u of width; explicit `scale` honoured; `backboard` defaults **OFF inside a park** — round-2 safeguard, a marquee backboard read as a monolithic black wall in ground shots — pass `backboard` to opt back in, and buildNeonSign then hugs the text and area-caps the slab), **`<DanceFloorR position size tile rotation>`**, **`<Scenery name position scale seed rotation>`** (SceneryPack catalog; round-6: registers its GROUND-CONTACT footprint so `validatePark` fails a piece planted in the water or standing in a path slab — plaza dressing exempt), **`<Lights from to poleHeight bulbs colors sag>`** (two real light poles + the catenary span hook-to-hook). Fencing lives in its own component — `import { Fence } from '../Fence'`: **`<Fence from to style height/>`** or **`<Fence points closed/>`** for a polygon (wood post-and-rail / metal queue railing / clipped hedge; from/to are WORLD xz so it takes no `position`, and every run registers as a guest BLOCKER — leave a GATEWAY where a street crosses it).
- `position` props take `[x, z]` (y settles onto the plaza/terrain under it) or `[x, y, z]`; `rotation` is Y yaw in radians.

## Round-5 self-healing settle pass (runtime-derived state)

Once ALL children have mounted — before guests spawn and before `validatePark` reads anything — `<Park>` runs two self-healing passes over the RUNTIME-DERIVED state no static plan can reliably predict (derived/trimmed/flipped/audit-shifted rigs, compiled circuits):

1. **Corridor auto-resolution.** Every MOVABLE object (stalls via `<ConfigurableStall>`/`composableStall`, flat-ride rigs via `registerComposedRide`/`<FlatRide>`; tracked-circuit rides and streets never move) is swept against the registered coasters' 1.6-u track corridors (the same segment-OBB sweep `validatePark` runs). Collisions self-heal in quality tiers: an exit hut alone in a corridor relocates by itself (0.6-u steps, ≤ 3 u); otherwise the whole rig shifts outward along the least-move axis to the first clear cell (≤ 4 cells; axis before diagonal, no-overlap before keeps-pre-existing-overlaps, corridor-fully-clear before exit-follow-up, dry before wet, never onto a hill flank or out of bounds); a derived queue lane too long to fit anywhere trims (`mgr.resizeRideLane`, fewer slots) as the last resort. Every fix is recorded as a **§0-FATAL park lint** (round-6: `console.warn` + `report.warnings`, and `validatePark` fails it as check `autofix`) — a self-heal is a REPORT, not a pass; the `pinned` prop opts a ride/stall out (it then FAILs where it stands). `manager().corridorCells(name?)` exposes the corridor cells for planning.
2. **AUTO-keepDry (`reclampTerrain`).** All audited footprints (manager + `registerFootprint` extras + stall rects) plus the as-built circuits feed the ParkBuilder guard clamp; when anything was wet/bulged/burying, `<Terrain>` rebuilds the terrain mesh, climate/zone colours, `heightAt` sampler and lint IN PLACE (the auto-dressing re-settles onto the new ground). Authors' `<Terrain keepDry>` is a hint, not a requirement — but every self-heal is a warning: a layout that needed one was mis-planned.

## Round-6 safeguards — auto-fixes reach the GATE (§0's fatal-warnings policy)

`rules/park-generation.md` §0 calls every grid/closure/`placeAccess` warning FATAL, but before round 6 the wrappers' auto-fixes were console-only: a park shipped `ok: true` over a flipped `queueDir`, a 2.21-u causeway and a relocated exit hut. Now:

- **`park.reportLint(kind, detail, fatal?)`** (on the ParkContext) records a build-time lint/auto-fix event. `<Park>` hands the list to `validatePark`, which echoes ALL of them in the new **`report.warnings: { kind, detail, fatal }[]`** and promotes `fatal: true` ones into real `failures` with check **`'autofix'`** — plus every kind in validate.ts's `FATAL_LINT_KINDS`, so the gate owns the §0 policy even for lints recorded by a wrapper that cannot know it. FATAL today: `causeway`, `queueDirFlip` / `queueDirUnfixable`, `exitHutRelocated` / `exitHutUnfixable`, `corridorShift` / `corridorExitRelocated` / `corridorLaneTrim` / `corridorPinned` / `corridorUnresolved`, and (round-6) **`coaster:shortDrop`** — a first drop under RCT2's 0.9-u gate HALVES excitement/intensity/nausea (`RideRatings.cpp:1318`), so the coaster opens as a ride nobody rates; every §4 archetype publishes lift ≥ 1.0 precisely so this can be a hard failure. Reported but NOT fatal: `laneTrim` (the round-2 tail-on-node trim working as designed — it still starves queue slots, so it is worth reading), `exitSnapped`, `coaster:shortLength` (a short circuit is a deliberate kiddie-coaster choice). **An empty `warnings` array is the only truly clean result.**
- **`park.registerPlanted({ label, x, z, r })`** — `<Scenery>`/`<Placed>` register their ground-contact footprint, and `validatePark` gains a **`scenery`** check: nothing planted may stand in the water (`terrainLint.isDry`) or inside a rendered path slab (plaza dressing exempt; the blocking radius caps at 0.6 u so a walk-in gazebo abutting a path stays legal).
- **Hard `bounds` check** — every audited footprint's SWEPT corners and every GameManager-derived queue-tail/exit attach node must sit inside ±size/2. `resolveQueueOrientation` now also tests the LANE rect and its derived TAIL for bounds (it used to test only the hut), so an orientation that would put a queue tail off the plot is flipped away from instead of shipped.
- **Strict track-corridor re-audit** — beside the 1.6-u corridor / 2.2-u ground clearance, every audited rect is re-swept at 2.2 u wide against the obstacle's OWN ROOF (hut 1.5 u, stall canopy 2.1, lane 0.45, pad 0.6, +0.3 u clearance). A hut the runtime relocated 0.96 u from the rails with the track 0.59 u off the ground used to pass; a roof-skim now FAILs.
- **`<Coaster>` crash gate in BOTH modes** — the energy-paced `replayCoasterForces` profile (the same physics `validatePark` and `rateCoaster` use) runs on the as-built world points for `points` AND `pieces` mode. Over the 1.5 g no-upstop derail guard (×0.85 margin) the circuit is FATAL: translucent red track, no GameManager registration. A 1.46 g circuit used to print "points-mode checks → design ok: true" and carry guests.
- **Derived exits snap to the paving** — `registerComposedRide` re-picks among the ride's four flush pad-edge cells (never the queue's own side) the one closest to a street node when that is ≥ 1 tile better, staying dry, in bounds and clear of every audited footprint. Derived exits used to land 3.9-4.8 u out in the grass.
- **SOLIDITY (`park.registerBlocker`) — guests no longer walk through things.** Guests used to clip straight through fountain basins, ride bodies and fences. Now every solid object registers a world-space OBB/circle with the GameManager's **blocker registry** (GameManager/Context.md "Blockers"): the routing layer refuses path edges that cross one, off-network waypoint hops SLIDE along the edge instead of entering, and `validatePark` gains a **`blockers`** check — no rendered street edge may run through a blocker (sampled every ~0.3 u; access spurs exempt) and every ride's queue tail must stay reachable from the gate with the blockers respected. Registered automatically: each ride's boarding pad + BODY footprint (`registerComposedRide`/`<FlatRide>` measure the built visual), each stall's body (the serving front stays walkable), `<Fountain>` (a circle at the basin radius), `<Restroom>` (hut solid, doorway clear), both queue-lane railings, and every `<Fence>` run. Relocations (`moveRide`/`moveStall`/`resizeRideLane`, the corridor auto-resolver) move the blockers with the rig. **Fence a boundary with a GATEWAY where a street crosses it** (two runs with a gap, or `<Fence inset>`) — a fence laid across a street is a hard FAIL, not a lint.

## Round-7 safeguards — the STREET/PLACEMENT layer (rules §0.14-§0.18)

Round 7's park scored its coaster 8/8 and still failed `validatePark` with 34 failures — EVERY one of them in the placement layer. These close those defect classes at MOUNT time, with an actionable message and a suggested cell, instead of as downstream FAILs:

- **Pads off the lattice.** `registerComposedRide` and `<ConfigurableStall>` audit the mounted pad against the RENDERED street lattice (`lintPadOffLattice`). A pad INTERSECTING a slab is a §0-FATAL **`padOnStreet`** lint; a ride pad inside the 1.8-u §0.14 margin but clear of the slab is a **`padNearStreet`** warning. Both print the nearest legal cell, computed with the same **`offPathCell(net, [x, z], { clear })`** / **`pathClearance(net, [x, z])`** helpers authors can call (exported from `../Park`). A SHOP is audited on its SOLID BODY only (hx 0.6 × hz 0.42) — kiosks are SUPPOSED to abut the street, so a `<Bazaar>`'s stalls may flank its own aisle.
- **`queue.anchor` is the HEAD.** An explicit anchor landing ON a street node raises a §0-FATAL **`queueAnchorIsHead`** lint printing the head coordinate that would have put the TAIL there (`tail − dir·(laneLenOf(capacity) + 0.35)`). Round 7 got this wrong on five rides — and never saw it, because `composableRide` was dropping `queue` (and `name`/`capacity`/`intensity`/…) into the visual builder's props instead of forwarding them to the chassis. **They are forwarded now.**
- **Two rides, one tail node** → §0-FATAL **`queueTailShared`** (one cell cannot be the entrance to two queues).
- **`<Paths>` derives ONE level from the MEDIAN ground** under its nodes (not the max) whenever the node spread exceeds 0.35, auto-ramping the outliers (`pathLevelMedian`, non-fatal) instead of hoisting the whole street onto berms. A span over **2.0 u** of air, or one whose ground dips under the waterline, is **NOT BUILT** — the edge is dropped and a §0-FATAL `causewayRefused` / `latticeInWater` lint says so, which then manufactures the DOWNSTREAM `accessibility` failures for whatever sat behind the hole.
- **Composed-terrain query API** (`park.terrain`, `park.isDry(cell)`, `park.isDryCell(cell)`): the §1 seed table's water coordinates are PRE-GUARD and move when `keepDry` forces a re-pick, so authors can finally read where the lake LANDED. `<Scenery>`/`<Placed>` refuse to plant in OPEN water (§0-FATAL `plantedInWater`); a marginal shoreline cell is kept and the AUTO-keepDry pass raises a dry bank under it (`plantedWetCell`) — planted footprints now join that sweep.
- **Stalls take the object form** `register={{ name, price, value, item }}` (it used to be a rides-only spelling that stalls silently ignored, so parks shipped catalog default names). Duplicate stall names and duplicate/unnamed registered CIRCUITS warn: the manager and the corridor sweep both key on the name.

Rules and limitations:

- **Deterministic only** — wrappers use hashed-sine randomness seeded off `<Park seed>`; never `Math.random`.
- **Prop changes REMOUNT the object** (rebuild + dispose). GameManager registrations (rides, stalls, restrooms, the gate) can NOT be unregistered — to change sim config, remount the whole `<Park>` with a `key`. Builder-function props (`build`) are not remount keys; keep them stable.
- **Preview-only rides have no builders yet** (FerrisWheel, Carousel, the four food shops…): compose them via `<Placed>`+`usePark().manager()` today; extracting their builders into typed wrappers is future work. `<Coaster>` + `<FlatRide>` + the amenity set cover composition now.
- **The worked example is `DistrictPark`** (`Park.previews.tsx`, preview 1): a size-48 park whose streets are FUSED by `buildParkNet` from a `<FountainPlaza>` + `<Bazaar>` + `<Boulevard>` plus a 13-node spine, with a pieces-mode §4.0-A flagship, three flats on cell interiors, and the composed water read from a guarded probe — `validatePark ok: true`, 0 failures. `DemoPark` remains as the COMPACT size-16 variant, but it is NOT the layout to copy (hand-written lattice, points-mode coaster): pointing agents at it is what produced four hand-rolled-grid parks in rounds 6-7.
